# lumos_access_policy (Resource)

An access policy: the apps and entitlements that identities matching its condition can get. Destroying it doesn't revoke access already granted through it.

## Example Usage

```terraform
# Everyone with an example.com address can request the wiki, pre-approved,
# and the deploy dashboard's Admin entitlement.
resource "lumos_access_policy" "engineering" {
  name                   = "Engineering tools"
  business_justification = "Engineers need the wiki and deploy access to ship."
  status                 = "published"
  is_enabled             = true

  access_condition = jsonencode({
    attribute = { label = "Email", value = "identity.email" }
    ends_with = { label = "@example.com", value = "@example.com" }
  })

  apps = [
    {
      # No entitlements: grants the app itself.
      id             = lumos_app.wiki.id
      is_preapproved = true
    },
    {
      id           = lumos_app.deploy_dashboard.id
      entitlements = [{ id = lumos_entitlement.deploy_admin.id }]
    },
  ]
}
```

## Schema

### Required

- `apps` (Attributes Set) The apps granted by this access policy. (see [below for nested schema](#nestedatt--apps))
- `business_justification` (String) Explanation for why this policy exists.
- `is_enabled` (Boolean) Whether the policy is in effect. Only a published policy can be enabled.
- `name` (String) The name of the access policy.
- `status` (String) `draft` or `published`. A published policy can't go back to `draft`. must be one of ["draft", "published"]

### Optional

- `access_condition` (String) The condition an identity must match for the policy to apply, as a Lumos condition written with `jsonencode`. Give every attribute and value as `{ label, value }`, the form Lumos reads back. Leave it out when `is_everyone_condition` is `true`. See [building conditions in Lumos](https://docs.lumos.com/kb/life_cycle_management/building-conditions-in-lumos). Parsed as JSON.
- `is_everyone_condition` (Boolean) Whether the policy applies to everyone in the organization. Set it to `true` instead of setting `access_condition`. Default: false

## Behavior

* **Who the policy applies to** is either everyone (`is_everyone_condition = true`) or the identities matching `access_condition`, never both. Write `access_condition` with `jsonencode`, giving every attribute and value as `{ label, value }` as in the example: that's the form Lumos stores and reads back, so any other form shows a change on every plan.
* **Grants:** each entry in `apps` grants the app itself when it has no `entitlements`, or the listed entitlements otherwise. Order doesn't matter.
* **`status` and `is_enabled` are required.** They always have a value, and a policy has no unset state to clear them to. A published policy can't go back to `draft`, a draft can't be enabled, and two published policies can't share a condition; Lumos refuses each of these and the apply fails with its error.
* **Editing a published policy publishes the change** in the same apply.
* **Drafts started in the Lumos UI:** while a published policy has an unpublished draft from the UI, Lumos refuses edits to it, and the apply fails until that draft is published or discarded.

## Destroy behavior

Destroy deletes the policy and the pre-approval rules it created. It doesn't revoke access users already received through the policy.

To stop managing a policy without deleting it, use a `removed` block:

```terraform
removed {
  from = lumos_access_policy.engineering

  lifecycle {
    destroy = false
  }
}
```

## Import

In Terraform v1.5.0 and later, an [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the policy's ID:

```terraform
import {
  to = lumos_access_policy.engineering
  id = "<access policy id>"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can also be used:

```shell
terraform import lumos_access_policy.engineering "<access policy id>"
```
